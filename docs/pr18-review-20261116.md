## Corrected behavior

- Remove `CraftSyncGuard`. The original guard recorded a pending inventory
  change after `mc_do` was merely accepted, then blocked another craft without
  the corresponding terminal receipt. The core owns action sequencing and
  inventory confirmation; the host must not invent another completion gate.
- Use the installed core's public `MovementProgress`, which distinguishes
  modifier-key patterns from unknown directional/swimming motion. Do not add
  a second, less precise implementation to this adapter. Request repetition
  alone is not proof that the character failed to move.
- Retain optional hunger advice (default threshold 15, zero disables it).
  Missing/nonfinite food remains unknown; advice does not block action,
  overwrite other notices, clear failure, or claim that eating occurred.
- Finite-goal default call budget changes from 30 to 80. Continuous mode
  retains its existing unbounded call budget and lifecycle. A pause or rest
  does not complete a goal.
