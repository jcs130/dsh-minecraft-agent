# 持续模式的宿主目标权限

适用于 `0.3.0-rc.25-preview.62`，在 DSH `0.2.1-rc.4`、核心 `0.5.7-rc.143` 的隔离消费环境验证。源码、打包产物、现役加载和实服效果分别验收。

## 问题和最小复现

原生 DSH 的 `update_goal pause` 需要当前轮具有直接的人类授权。自主游戏轮不能因为想暂时等待，就暂停主人的长期目标。此前持续模式仍给模型声明了完整的目标写工具及其说明，模型可能不断尝试 `pause`。一次实测记录中有 248 次相同权限拒绝；这是重复工具调用的数量，不能当作 248 次独立任务失败或服务器故障。

离线复现使用真实的官方 Toolkit：建立一个 active/armed 的合成目标，以没有人类消息的自主轮执行 `update_goal({goal_id, revision, action:'pause'})`，得到原生 `GOAL_TOOL_AUTHORITY_REQUIRED`。目标保持 active，原始错误不变，不连接 Minecraft 或模型。

## 能力声明与权限一致

continuous 模式仍使用官方 `get_goal` 实现，只向该 Agent 的模型声明目标读取。`create_goal` / `update_goal` 不在它实际组装的工具列表中，继承自预设的写工具也通过公开 scope 限制隐藏；目标说明同时覆盖为只读政策。加载后核对真实 scoped schemas，不根据期望配置假称限制成功。

主人的原生 GoalService、UI/API 和其他 Agent 的作用域不变。有限预算的 bounded 模式挂载原插件。游戏阶段的拆解、执行、等待和结果验证继续使用已声明的游戏能力。游戏完成一个阶段不等于结束宿主长期目标；本插件不自动授权 pause，不创建替代目标，也不把拒绝包装成成功。

官方预设在父作用域挂载工具，已覆盖验证。若自定义预设在完全相同的 Agent scope 注册目标写工具，原生限制接口不能屏蔽自己的注册项；此时明确报配置冲突，不能声称只读生效。

## 重复拒绝的有界恢复

观察最终 `tools/result` 的原生结构化错误码；不从错误文案猜权限。相同 session、目标、身体 run、工具、操作和错误码累计达到 3 次时，在该 Agent 已有且 active/armed 的 pre-step 中，通过原生 `inject` 向后续自然步骤排入一次能力纠正。它不启动或唤醒驱动，不另建回合，不自动重试工具、不修改工具回执。通知使用 `mc-permission-recovery` 来源，绝不能冒充直接人类授权。

旧历史对已屏蔽目标工具的调用会保留真实 `ToolNotFoundError`，同样可产生一次纠正。其他任意缺失游戏工具不会因此被视作权限拒绝。用户暂停、已中止步骤、其他 Agent 或其他身体 run 均不能被此机制恢复。

每个拒绝类别最多尝试一次通知；排入不等于模型已读、请求已派发或游戏已恢复。如果派送失败，仅记录计数，不形成重试风暴。最多保留 16 个类别和 128 个去重调用标识。计数不因目标 revision 改变而清零。元数据写入当前会话的 `permission-recovery.json`，仅保留标识、操作、错误码、数量与 attempted/queued，不保存参数正文、提示词、回答、思考或凭据。持久化异常不会替换原始失败。

`status.json` 新增 `hostGoalCapabilities` 和 `permissionRecovery`。前者只有实际能力核验成功才写入；后者的 queued 只能证明通知排入，不能证明游戏动作成功。

## 验证与加载

隔离测试覆盖官方权限拒绝、最终组装工具与政策、父预设、主人 API、其他 Agent、卸载恢复、bounded 模式、248 次拒绝回放、持久化恢复、取消、重复事件及通知失败。未使用外部模型，没有登录游戏或执行身体操作。

历史会话可能还持有旧工具声明。部署必须确认本 Agent 的模型、身体、语音及未知动作账本处于安全边界，保留原 session、goal、记忆和回执。旧适配器卸载会尝试游戏告别聊天，不能把普通热卸载当成零游戏动作；应先明确具体迁移方式和影响，再协调加载。不能用源码测试代替现役加载或脱困、持续讲话的实服验收。
