# AuthMe 密码登录修复（rc.16 候选）

rc.15 的侧栏已经保存了密码，但它使用的旧核心只按提示前缀匹配。
AuthMe 英文提示在 Please 后有逗号，因而密码一次也没有提交。
其标准成功回执也未被旧配置覆盖，只修请求匹配仍可能在提交后超时。
消息定义可查 [AuthMe 官方资源](https://github.com/AuthMe/AuthMeReloaded/blob/master/authme-core/src/main/resources/messages/messages_en.yml)。

修复在共享 `agent-mc-world@0.5.7-rc.83`，核心主干提交
`f8c09b2436f9a2ef04da3924ad5fccd715553475`。DSH 只更新锁定依赖，
不复制登录逻辑。侧栏已有的私有密码文件和账号配置继续使用，
普通离线服仍可不填密码。

核心仅对显式配置、匹配当前服务器和账号的 login 操作，识别可信系统消息中的
`/login` 请求；`/loginx`、`/register` 和玩家聊天不触发兜底。
每连接至多提交一次现有密码，提交本身不放行身体。
明确成功回执或会话续用确认后，仍需真实出生点就绪才允许行动。
已配置结构化认证的连接，其拒绝状态不被文本兼容回执覆盖。
错误密码会停止，不反复尝试；不自动注册或修改密码。

超时原因贯穿断线回调、连接状态和面板提示：

| 原因 | 显示含义 |
| --- | --- |
| request-not-detected | 未识别到登录提示，尚未提交密码 |
| credential-read-timeout | 登录凭据读取超时，尚未提交密码 |
| confirmation-timeout | 密码已提交，等待认证确认超时；不等于密码错误 |

核心完整回归 2035 项通过、1 项可选测试跳过；构建、类型检查与打包校验通过。
独立安装的归档通过 Java 1.21.1 本机协议测试世界：侧栏生成的真实私有配置，
首次密码登录与会话续用两场景均就绪，且能通过 SDK/MCP 读取工具帮助。
该测试模拟 AuthMe 官方回执，未启动真实 AuthMe/Paper 插件，也不代表实服游玩验收。
运行状态及事件中检查不到测试密码，没有外部模型调用。

当前发布状态见[分发记录](registry-release.md)。升级和回滚保留 profile、账号私有目录、
原会话、目标与游戏记忆；不通过重建身份或清空数据解决登录问题。
