# 攻略续读与有证据的短反思

使用支持该契约的 MC 核心时，插件会为过长的只读攻略正文保留不可变的
`log:` 原文引用。模型看到的 `meta.textPage.next` 是真实续读入口，游标只跳过
实际展示过的文字。默认精简工具集包含 `*_read_text`；用户明确隐藏该工具时，
插件不会生成不可用的续读提示。公开旧核心仍沿用其原有展示方式。

重复只读的比较和在途判断由核心 `ReadProgressBook` 提供，适配器仅消费证据。
同一查询和完整结果版本反复出现、且本运行没有登记在途/跨代未决任务、
待返回调用和战术调用时，才算没有新增信息。新页面、新结果或现场变化重新计数。
该计数不等于目标失败，也不授权取消工作、执行攻略指令或重投旧未知动作。

启用现有 `reflection` 选项后，达到配置阈值的重复只读证据可以让下一次本来就
会发生的模型请求使用一次 `low`。随后恢复原无思考设置，保留用户显式选择的
思考等级、模型与输出预算。现有冷却与请求间隔仍生效；同一版本的重复证据
在进程恢复后也不会重复购买反思。没有新增诊断推理。

持续无进展时沿用原有临时休整策略，保留目标和会话；新休整窗口清空只读连计，
避免恢复后立刻再次触发旧计数。状态里的 `readProgress` 只含哈希与计数，
`executionState` 是本运行登记状态，不是所有历史进程或服务器工作的全局证明。
缺失的引擎耗时、排队和用量仍是未知，不用工具耗时或客户端等待时间替代。
