# 生存攻略、步骤脚本与决策

攻略数据和操作能力都由共享 `agent-mc-world` 提供，DSH 插件不维护另一套规则或复制知识库。宿主负责目标、模型、人格和何时采用资料。

| 入口 | 能提供什么 | 不能证明什么 |
| --- | --- | --- |
| `mc_knowledge` | 本地、带版本和来源的原版资料；先 search 摘要，再 get 一个返回 ID | 当前材料、附近资源、服务器改版配方或动作成功 |
| `mc_script` | 按需发现和读取已有步骤脚本、方法及前提 | 当前角色已满足材料、能力、权限，或应当自动运行 |
| `mc_memory` | 随服务器／账号／Agent 保存的资源、兴趣点、历史经验、失败与方法记录 | 当前可见性、材料仍在原地或方法对所有场景有效 |
| 当前事实、动作工具与回执 | 当前读到的状态、执行及结案证据 | 仅接受请求不代表用户目标已完成 |

默认精简工具集保留以上入口；如果用户显式排除某个工具，提示不会要求调用被排除的工具。可选服务器包使用自己的实际前缀，例如 `mymc_knowledge`，不会为兼容它另起知识库。

Java 1.21.1 的随包生存卡片包括：

- `guide/bed`：床、羊毛、睡眠、跳夜和重生点。
- `guide/night_shelter`：缺床时的临时庇护与等待天亮。
- `guide/equipment`：武器、防具、工具和准备条件。
- `guide/base`：据点、工作台与炉子。
- `guide/storage`：储物、箱子与物资整理。
- `guide/farming`：耕地、种植、成熟与补种。

食物、烹饪、恢复及物品／方块／配方索引也通过同一入口检索。先用 search 发现条目；其他 Java 版本以工具实际报告的覆盖为准，不把 1.21.1 语义冒充所有版本兼容。

例如主人要求“自主生存”，Agent 可根据实际夜色、饥饿与背包比较食物、睡眠、避险和装备，再读取相关卡片、配方或脚本，选择一个可验证的小阶段。遇到材料不足应改方案或补材料，执行后查看真正回执并更新笔记。这是供模型比较方案的资料，不是“先砍树再挖矿”的固定任务清单；聊天回应也不自动结束整个生存目标。

宿主仅增加稳定的简短使用提示，不自动下载数据、注入整本攻略、发起检索循环、嵌入向量或调用额外模型。资料保留在有界工具历史，当前状态仍在请求尾部。`test/core-consumer.test.mjs` 已通过打包核心的实际 MCP 读取上述六张卡片，核对 SDK 输出与来源、默认工具可发现性，以及读取过程零游戏连接。

rc.21 可通过核心 rc.88 显式配置 [MineDojo 本地索引](minedojo-knowledge.md)，支持全文与 CPU 词元向量；配置后沿用同一个 `mc_knowledge` 工具，以 `source:minedojo` 查询。索引默认不启用，完整语料不随包分发。原始格式和版本边界仍见[源码与资料审计](https://github.com/jcs130/minecraft-ai-friend/blob/main/packages/agent-mc-world/docs/research/minedojo-knowledge-20261020.md)。
