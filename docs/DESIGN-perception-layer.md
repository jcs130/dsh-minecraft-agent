## 1. 设计原则（5 条）

1. **分档**：每步必进的和按需拉取的必须分开。每步注入的东西是有 token 代价的，只能放「忘了就会死」的信息。
2. **变了才说**：增量 + 时间戳；不变就闭嘴（血/食/位置已经这么做了，其余照此办理）。
3. **亲眼看/亲耳听才具名**（真实性铁律）：视线遮挡剔除、玩家去名化、未加载区块不可知。**感知层不许全知**。
4. **感知带时间与版本**：每条感知可被引用（反思要说「我当时以为……」，就必须能取回当时那条）。
5. **事实与剧情分开**：物理事实来自 mineflayer；剧情事实（神谕/NPC/广播）走文字通道。**碰 RCON 是红线**（世界侧归天神）。

## 2. 三档 + 元感知

| 档 | 时机 | 载体 | 成本 | 判据 |
|---|---|---|---|---|
| **① 底线注入** | 每步（system prompt 组装） | `systemPrompt.context({name:'mc:status', text: perceive})` | 每步 ~10-15 行 token | 「忘了就会死/就会空转」 |
| **② 事件增量** | 事件发生时入队，下一步随底线吐出 | 内存队列 → 同一 context | 零额外调用 | 「发生了，且不能等到下次主动查」 |
| **③ 按需工具** | agent 自己决定要看 | `mc_status` / `mc_scan` / `mc_map` / `mc_see` / `mc_view_chest` / `mc_view_furnace` | 一次工具调用 | 「想知道时再知道，且它自己知道要查」 |
| **④ 元感知** | 每步（与①同批） | 同一 context | 极低 | 让 agent 自己看见「我在空转/停滞/被威胁」 |

## 4. 事件流清单（现状 vs 可用）

**已听（5 个）**：`chat`、`whisper`、`message`、`death`、`error`/`end`。
**建议听（按价值排序）**：
1. `health`（受伤：扣多少、什么时候 —— 死亡前就能反应）
2. `itemDrop` / `playerCollect`（采集/战斗的即时回报与丢失）
3. `blockUpdate` / `blockPlaced`（别人的动作 = 世界在变）
4. `rain` / `weatherUpdate`（天气与雷暴）
5. `soundEffectHeard` / `chestLidMove` / `pistonMove`（听觉，见 3.7）
6. `entityHurt` / `entityDead`（我打中了没、谁死了）
7. `playerJoined` / `playerLeft`（有人来了）
8. `sleep` / `wake`（睡眠边界，夜间事务已有钩子）
9. `respawn` / `spawnReset`（重生点）
10. `experience`（升级）
11. `blockBreakProgressObserved`（有人在挖）
12. `time`（昼夜切换精确边界）
13. `title` / `actionBar` / `bossbar` / `scoreUpdated`（服务器剧情与任务通道）

**事件流的落点**：入队 → 下一步随底线吐出（②档）；同时**落 `mc-store` 单库**（供反思与慢循环做证据）。

## 5. 每步注入契约（①+④，建议定死）

```
[Day 12 08:31 昼]
♥血量 14/20            ← 变化或 ≤8 才出
🍗饱食 12/20           ← 变化或 ≤8 才出
🫧氧气 6/10 ⚠将溺水    ← 新增：<10 才出
📍你移到 (128, 64, -301)  ← 跨 16 格区段才出
🌧 雷雨               ← 新增：天气变化才出
💬<玩家>说了什么…      ← 有新聊天才出
<NPC/神谕台词>         ← 有新台词才出
⚠ 你被 <骷髅> 射中 -3   ← 新增：受伤事件（带来源方向，不带全知坐标）
🪨<玩家> 打碎了你身边的石头 ← 新增：近处方块变化
【脉搏】你在 (128,64,-301)（昼），近处可攻击怪：2 个
【最近动作】移动(去120,64,-295) => 到达 —— 已连续 3 轮同类型
【停滞】已连续 5 轮待在同一区域没挪窝
```

预算：**常态 ≤ 8 行，异常态 ≤ 15 行**。任何新增字段必须先证明「不加它会死或会空转」，否则进 ③ 档。

## 6. 差距与优先级

**P0（安全直接相关，先做）**
1. 溺水（`oxygenLevel`）
2. 天气/雷暴（`isRaining`/`thunderState`）
3. 受伤事件与来源方向（`'health'` + 最近威胁方位）—— 死亡前就能反应
4. 掉落物（`'itemDrop'`/`'playerCollect'`）—— 采集与战斗的即时反馈
5. **认知边界**（chunk 加载状态）—— 反全知，直接服务真实性铁律
6. 工具耐久（字段需验证）

**P1**
7. 近处方块变化（有人在我身边挖/放）
8. 听觉三件套（声音/箱子盖/活塞）
9. 玩家进出、睡眠/醒来、重生
10. 药水效果、维度、等级

**P2**
11. 服务器通道（title/actionBar/scoreboard/bossbar）
12. 光照、群系、月相、高度范围等世界观上下文
13. 聊天格式解析（`chatPatterns`）、音符盒

**不做**
- RCON / 服务端内部数据（红线，世界侧归天神）
- 未加载区块的方块、视线外实体的名字/坐标（真实性铁律）
- 每步注入背包/地形/实体清单（已下沉，别再拉回来）

## 8. 复审（第二轮，2026-09-20）：实测查出 7 处缺陷并修正

方法：不再靠读代码判断，而是写了个**注入预算探针**（`test/perception-report.mjs`）——
用假 bot 驱动 `status()`，把各场景的真实输出打出来数行数/字符数。缺陷都是这么露出来的。

|---|---|---|---|

**两次同类真 bug**（都属于「双记账」：事件处理器与每步注入抢同一份状态）：

- `health` 处理器同理（已先修）。

### 锁进测试的不变量（`test/perception-smoke.mjs` 第 [14] 段）
1. 常态步**只有 1 行**且 ≤90 字符；首次接入 ≤3 行
2. 一次受击**只出现一条**陈述，且来源必须是真值（不靠"最近威胁"猜）
3. 位置、威胁事实在一步里各**只出现一次**
4. 危险行**边沿触发**：变化时报，随后不重复
