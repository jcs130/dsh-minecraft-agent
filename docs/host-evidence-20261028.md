# Host evidence and progress handling

These changes affect the DSH adapter. The shared Minecraft core continues to own perception, actions, task identity and outcome evidence; the host decides how to present evidence and continue a goal. No alternate game executor or model loop is introduced.

- Render corrective `hostNotice` before a potentially long structured receipt, so the existing model-visible cap does not remove the correction. The original durable receipt is unchanged and remains accessible through history.
- Keep the core's typed `repeatFailure` evidence outside the condensed event prose: original run/task identity, attempts, scope, observation comparison and terminal phase. Unknown comparisons remain unknown. Keep at most three recent records and expire them; these historical records do not prove current inventory, completion or permission to retry.
- Include asynchronous method failures by immutable source hash and terminal method ID. Admission is not success. The bounded error excerpt is untrusted receipt data, so it cannot grant tool permissions. Do not blindly rerun an identical method that failed before its first SDK call.
- Treat the current `*_observe` capability, as well as scout/visual/risk, as observations for progress feedback. Observe/query reads do not count as physical actions. Progress feedback remains advisory; controlled continuation rests retain the original goal instead of reporting it complete.
- Continue cleanup after session or transport failures, including closing the local panel and MCP server. A browser-only bundle row must keep an empty `configFile`; only the configured harness row owns the body.

The core canonicalizes JSON, preserves arrays, explicit null/false/zero and removals, verifies the exact baseline and content revision, and emits a fresh snapshot for a new run/dimension or periodically. Preparing a frame never advances its baseline; admission does. No model, host persona, body policy or file store is added to the core.

The DSH adapter registers the update as a trailing native runtime-context section. It commits only the frame actually admitted to the native durable session. It retires older volatile snapshots once when migrating, rather than rewriting earlier input on every step. Successful native compaction resets the baseline; failed compaction leaves it intact. A baseline fault stops dispatch instead of sending an inconsistent input. Original user history and paired tool results remain native DSH responsibilities.

`compaction.strategy: "evidence"` is an **opt-in private experiment**; the default remains `guided-model`. It subclasses only the public native `BasicCompactionEngine.summarize` seam. It prepares a transcript index containing every recorded text user input verbatim and in order, with its original principal, the current structured goal, recent tool receipts, unresolved call references and native history positions. Assistant text is marked unverified; reasoning blocks are excluded. Shortened receipts are explicit excerpts and originals remain available through the registered `dsh_history` tool. Non-text user requests are rejected instead of silently discarded. The index grants no new authority or permission to replay an uncertain action.

The native engine still selects the range, checks tool-call pairing and useful shrinkage, commits the checkpoint, and records success/failure. The backend makes no inference call and therefore supplies no invented token usage, reasoning budget or execution time. Its status callback measures preparation, not a successful native commit; inspect `compaction/end` before reporting completion. A composed DSH preset retains its own compaction service.
